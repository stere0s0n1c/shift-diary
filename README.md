# Дневник смен водителя

Тестовое задание arqa: сервер отдаёт поездки и сводку за день, клиент показывает сводку и переключает дни, поездки добавляются через API с проверкой данных и защитой от дублей.

Стек: Swift 6, сервер на [Vapor](https://vapor.codes), консольный клиент, тесты на Swift Testing и XCTVapor.

## Запуск

Нужен Swift 6.0+ (Xcode 16+ на macOS).

```bash
# сервер на http://127.0.0.1:8080, данные — data/trips.json
swift run shift-server serve

# во втором терминале — клиент
swift run shift-diary --date 2026-10-01
```

В клиенте: `n` — следующий день, `p` — предыдущий, `2026-10-02` — перейти к дате, `q` — выход.
Без `--date` клиент открывает последний день, в котором есть поездки.

Тесты:

```bash
swift test
```

Настройки сервера через переменные окружения:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `SHIFT_DATA` | `data/trips.json` | файл с поездками; новые поездки дописываются туда же |
| `SHIFT_TZ` | `Asia/Almaty` | часовой пояс водителя, по нему поездки раскладываются по дням |

## API

### `GET /api/days/{YYYY-MM-DD}` — сводка и поездки за день

```bash
curl http://127.0.0.1:8080/api/days/2026-10-01
```

```json
{
  "date": "2026-10-01",
  "utcOffsetSeconds": 18000,
  "summary": { "tripCount": 2, "revenue": 3900, "commission": 585, "net": 3315, "cash": 1500, "card": 2400 },
  "trips": [
    { "id": "t1", "start": "2026-10-01T08:10:00+05:00", "end": "2026-10-01T08:32:00+05:00", "amount": 2400, "payment": "card", "commission": 360 },
    { "id": "t2", "start": "2026-10-01T09:05:00+05:00", "end": "2026-10-01T09:20:00+05:00", "amount": 1500, "payment": "cash", "commission": 225 }
  ]
}
```

`net` — «на руки» = выручка − комиссия. `cash` / `card` — выручка по способу оплаты.
День без поездок возвращает нули, а не ошибку. Неверная дата (`2026-13-01`) — `400`.

### `GET /api/days` — дни, в которых есть поездки

```json
{ "days": ["2026-10-01", "2026-10-02"] }
```

### `POST /api/trips` — добавить поездку

```bash
curl -X POST http://127.0.0.1:8080/api/trips \
  -H 'Content-Type: application/json' \
  -d '{"id":"t6","start":"2026-10-03T10:00:00+05:00","end":"2026-10-03T10:20:00+05:00","amount":1800,"payment":"cash","commission":270}'
```

| Ситуация | Ответ |
|---|---|
| новая поездка | `201`, `{"created": true, "trip": {...}}` |
| та же поездка повторно (тот же `id`, те же данные) | `200`, `{"created": false, ...}` — дубль не создаётся |
| тот же `id`, но другие данные | `409 Conflict` |
| `amount <= 0`, `end <= start`, комиссия < 0 или больше суммы, пустой `id` | `422`, в `reason` — все ошибки сразу |
| битый JSON, неизвестный `payment` | `400` |

## Как устроено

- `ShiftCore` — модели, расчёт сводки, проверка поездки, хранилище. Не зависит от Vapor, поэтому логика тестируется без сервера.
- `ShiftAPI` — HTTP-слой: три маршрута поверх `ShiftCore`.
- `ShiftServer` — точка входа сервера, `ShiftClient` — консольный клиент.

Решения, которые стоит проверить на ревью:

- **Защита от дублей.** Ключ идемпотентности — `id` поездки. Клиент, не получивший ответа, может повторить запрос: если данные совпадают, сервер отвечает `200` с уже сохранённой поездкой. Если под тем же `id` пришли другие данные, это не повтор, а ошибка клиента, поэтому `409`, а не тихая перезапись.
- **Гонки.** Хранилище — `actor`, проверка «есть ли такой id» и запись идут атомарно. Тест шлёт 50 одинаковых запросов параллельно и проверяет, что запись одна.
- **Границы дня.** День считается по часовому поясу водителя (`Asia/Almaty`, UTC+5), а не по UTC. Поездка через полночь относится к дню начала.
- **Деньги** — целые тенге, как в исходных данных, без `Double`.
- **Хранение** — JSON-файл, запись атомарная. Если запись на диск не удалась, поездка не остаётся в памяти, чтобы память и файл не расходились. Для реального сервиса здесь была бы БД с уникальным индексом по `id`.

## Использование ИИ

Проект сделан с Claude Code: код, тесты и этот README написал агент. Результат проверялся сборкой, `swift test` и ручным прогоном сервера, `curl` и клиента.

Где ИИ ошибся и что исправлено:

- **Тест не компилировался.** В тесте пустого дня агент сравнивал массив литералов прямо внутри макроса `#expect`. Компилятор не смог вывести тип: `ambiguous use of operator '=='`. Исправлено явным типом массива.
- **Клиент выглядел неправильно, хотя тесты были зелёными.** Время выводилось через локализованный формат без ведущего нуля (`8:10`), колонки разъезжались, подпись «Наличные / карта» слипалась с суммой. Тесты этого не ловят, видно только при живом запуске. Переписано на фиксированный `HH:mm` и явное выравнивание колонок.
